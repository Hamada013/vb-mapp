# Code map (read this before opening files)

Static, no-framework PWA. Arabic-first (`lang="ar" dir="rtl"`), bilingual via `tr(en, ar)` in app.js and `data-en`/`data-ar` attributes in index.html. All data is in device `localStorage`. No build step for app code: edit files in `assets/` directly.

README.md (60 KB) is a change log of the clinical content. Don't read it in full; grep it for an item id when you need the reason behind a rule.

## Commands
- `npm test`: node unit tests (model, accounts, task-analysis, iep, goal-bank, games data).
- Browser tests (Playwright, run `npm install` first): `npm run test:browser | test:barriers | test:transitions | test:report | test:lifecycle | test:navigation | test:dialogs | test:games | ...` (see package.json). Add `VBMAPP_ENGINE=webkit` to test Safari.
- `node tests/one-way-links.cjs`: must pass. Never link to the main speech website.
- `npm run build`: regenerates `assets/pwa-release.js`. CI (`.github/workflows/pages.yml`) runs build, stage and tests, then deploys `output/pages` on push to main.
- `scripts/stage-site.cjs` omits AGENTS.md/CLAUDE.md from the published site.

## Conventions
- No emoji anywhere: use outline icons from `assets/icons.js` (`VBIcon(name)`), and words in plain-text notes.
- Every user-visible string is bilingual: `tr('English','عربي')`.
- Completed assessments are immutable (`accounts.save`). Only report preferences may change.
- Keep the code style: compact single-line functions, template-string HTML, `esc()` for every interpolated value.
